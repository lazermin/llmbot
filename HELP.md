# llmbot 1.4.3

Личный Telegram-бот для текстовых запросов к LLM. Отправьте вопрос в личном чате. Бот сразу передаст его выбранной модели и покажет ответ после завершения генерации. Длинные ответы делятся на несколько сообщений.

Через прямой API DeepSeek бот умеет искать актуальные данные и читать веб-страницы. Ответы поддерживают выделение, команды, блоки кода и спойлеры Telegram.
Бот также читает PDF, DOCX и текстовые файлы и передаёт изображения в модель с поддержкой vision.

Бот запускается через Telegram long polling. На сервере нужны исходящие подключения к `api.telegram.org` и к выбранному API модели. Для установки зависимостей требуется доступ к PyPI или настроенному зеркалу. Входящий порт для бота не нужен.

## Установка

Требуется Python 3.10 или новее. Установщик поддерживает APT на Debian и Ubuntu, DNF или YUM на РЕД ОС, Fedora и системах семейства RHEL. При запуске обычным пользователем установщик использует `sudo`, если нужны системные пакеты. Окружение и зависимости бота находятся в каталоге `.venv`.

1. Создайте бота в [@BotFather](https://t.me/BotFather) и получите токен. Отображаемое имя можно задать как `llmbot`. Для уникального Telegram username выберите доступное имя с окончанием `bot`.
2. Узнайте числовой ID своей учётной записи Telegram, например через [@userinfobot](https://t.me/userinfobot). Введите его в `ADMIN_ID`. Этот аккаунт управляет доступом. Бот работает в личных чатах.
3. Распакуйте архив и запустите установщик в одном из двух режимов. Мастер запросит токен, ID и параметры модели, если настройки ещё не заполнены.

### Системная установка от root

```bash
unzip llmbot-1.4.3.zip
cd llmbot
bash install.sh
```

Установщик размещает программу и виртуальное окружение в `/opt/llmbot`, создаёт отдельного системного пользователя `llmbot` и запускает от его имени системный сервис `llmbot.service`. Сервис запускается при загрузке ОС. Исходный архив можно распаковать и запустить из `/root`.

Настройки хранятся в `/etc/llmbot/.env` с правами `640` и владельцем `root:llmbot`. При первой установке скрипт берёт настройки из `.env` рядом с `install.sh`, если файл уже заполнен. Повторный запуск сохраняет настройки и оба промпта.

```bash
systemctl status llmbot.service
systemctl restart llmbot.service
journalctl -u llmbot.service -f
```

Если этот же бот уже запущен как пользовательский сервис, остановите его командой `systemctl --user disable --now llmbot.service` из сессии того пользователя перед установкой системного сервиса.

### Установка от обычного пользователя

Распакуйте архив в постоянный каталог и выполните `bash install.sh` внутри `llmbot`. Установщик создаст пользовательский сервис `llmbot.service` и запустит его. Чтобы сервис стартовал при загрузке ОС и продолжал работать после выхода из SSH, используйте `bash install.sh --linger`. Для установки с уже заполненным конфигом скопируйте `.env.example` в `.env` и внесите параметры. При повторном запуске скрипт сохраняет существующий `.env`.

Если пользовательский systemd недоступен, установите зависимости и запустите бота вручную.

```bash
bash install.sh --no-service
.venv/bin/python bot.py
```

### Системные пакеты при ручной установке

| Система | Команды |
| --- | --- |
| Debian или Ubuntu с Python 3.10+ в штатном репозитории | `sudo apt-get update`, затем `sudo apt-get install python3 python3-venv ca-certificates` |
| РЕД ОС или Fedora с Python 3.10+ по умолчанию | `sudo dnf install python3 python3-pip ca-certificates` |
| RHEL 9 или совместимая система, где версия штатного `python3` ниже 3.10 | `sudo dnf install python3.11 python3.11-pip ca-certificates`, затем `LLMBOT_PYTHON=/usr/bin/python3.11 bash install.sh` |

Наличие версионных пакетов зависит от выпуска и подключённых репозиториев. Если штатный репозиторий предоставляет только Python ниже 3.10, установите подходящий Python из доступного репозитория и передайте его путь через `LLMBOT_PYTHON` при создании `.venv`.

## Конфигурация

| Параметр | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram от BotFather |
| `ADMIN_ID` | Положительный числовой Telegram ID владельца |
| `LLM_BASE_URL` | Базовый URL OpenAI-совместимого API. Сам бот обращается к `/chat/completions` относительно этого адреса |
| `LLM_MODEL` | Идентификатор модели у провайдера. Для Ollama используйте имя установленной модели из `ollama list` |
| `LLM_MODELS` | Дополнительные текстовые модели для команды `/model`, через запятую. Если параметр отсутствует, прямой API DeepSeek предлагает `deepseek-flash` и `deepseek-v4-pro`. Модель из `LLM_MODEL` всегда входит в список. |
| `LLM_API_KEY` | Ключ провайдера. При системной установке его можно перенести в зашифрованный credential, см. ниже. Для локальной Ollama без авторизации установите `ollama` |
| `LLM_TIMEOUT` | Время ожидания ответа в секундах, по умолчанию 120 |
| `HISTORY_TURNS` | Максимальное число последних пар вопрос–ответ на диалог, по умолчанию 4. Значение 0 отключает передачу предыдущих ответов. Прикреплённые файлы по-прежнему доступны в активном диалоге. |
| `LLM_WEB_TOOLS` | `auto` (по умолчанию) подключает веб-инструменты прямого API DeepSeek. `off` отключает автоматический поиск и команду `/web` |
| `LLM_VISION_MODEL` | `auto` (по умолчанию) использует `deepseek-flash` на прямом API DeepSeek. Для другого API укажите идентификатор модели, которая принимает изображения через Chat Completions. `off` отключает анализ изображений |

Примеры адресов и моделей. Доступные идентификаторы уточняйте у провайдера.

| Провайдер | `LLM_BASE_URL` | Пример `LLM_MODEL` |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| Ollama на том же сервере | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` |

В `prompt.txt` хранится системный промпт для инженерных и обычных вопросов. В `telegram-format.txt` — дополнительные правила разметки Telegram HTML. Бот преобразует разрешённую разметку в элементы форматирования Telegram и проверяет лимит при разбиении текста.

При системной установке редактируйте `/etc/llmbot/.env`, `/etc/llmbot/telegram-format.txt` или `/opt/llmbot/prompt.txt`, затем выполните `systemctl restart llmbot.service` от root. При пользовательской установке меняйте файлы в каталоге бота и выполните следующие команды.

```bash
.venv/bin/python bot.py --check-config
systemctl --user restart llmbot.service
```

Тексты вопросов и недавние ответы передаются выбранному LLM-провайдеру. История хранится в памяти процесса и сбрасывается при перезапуске. При пользовательской установке права на `.env` выставляются в `600`.

### Как перейти с DeepSeek на OpenAI API

1. Создайте ключ в проекте OpenAI API и настройте оплату API. У подписки ChatGPT Plus отдельный биллинг. [Ключи OpenAI API](https://platform.openai.com/api-keys) · [Биллинг ChatGPT и API](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)
2. Для системной установки остановите бота от root командой `systemctl stop llmbot.service` и откройте `/etc/llmbot/.env`. Для пользовательской установки используйте `systemctl --user stop llmbot.service` и файл `.env` в каталоге бота. Обновите параметры подключения. В примере `gpt-4.1-mini` используется для текста и анализа изображений. Если `LLM_MODELS` уже задан, оставьте в нём только модели нового провайдера. [Возможности GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)

   ```dotenv
   LLM_BASE_URL=https://api.openai.com/v1
   LLM_MODEL=gpt-4.1-mini
   LLM_MODELS=gpt-4.1-mini
   LLM_VISION_MODEL=gpt-4.1-mini
   ```

3. Установите ключ OpenAI одним из двух способов.

   - **Ключ хранится в `.env`.** Замените значение `LLM_API_KEY` в этом файле и запустите сервис командой `systemctl start llmbot.service` от root или `systemctl --user start llmbot.service` для пользовательской установки.
   - **Ключ зашифрован.** Запустите команду ниже от root и введите новый ключ в скрытом приглашении. Скрипт сам запустит сервис. Если замена завершилась ошибкой, верните в `.env` прежние параметры провайдера перед возобновлением работы бота.

   ```bash
   /opt/llmbot/.venv/bin/python /opt/llmbot/encrypt-api-key.py --replace
   ```

4. Отправьте боту `/status`, чтобы проверить выбранную модель, затем задайте обычный текстовый вопрос. Ответ модели подтвердит, что бот обращается к API с новым ключом. В этой версии команда `/web` доступна при прямом подключении к DeepSeek.

Команда `/model` переключает модели внутри настроенного провайдера. Для перехода на другой OpenAI-совместимый сервис повторите те же шаги с его URL, идентификаторами моделей и ключом.

## Шифрование ключа LLM

Для системного сервиса от root можно включить шифрование `LLM_API_KEY`. Поверх существующей установки сначала запустите `bash update.sh` из нового архива. Затем выполните от root:

```bash
/opt/llmbot/.venv/bin/python /opt/llmbot/encrypt-api-key.py
```

Скрипт возьмёт текущий ключ из `/etc/llmbot/.env`, проверит расшифровку в отдельном запуске systemd и перезапустит `llmbot.service`. После настройки ключ хранится в `/etc/llmbot/llm-api-key.cred`, а строки с `LLM_API_KEY` удаляются из `.env`. `BOT_TOKEN` остаётся в `.env`. Для ручной и пользовательской установок предусмотрено прежнее чтение из `.env`.

Нужны `systemd-creds`, `systemd-run` и поддержка `LoadCredentialEncrypted=`. По умолчанию скрипт использует режим `auto`. Параметр `--with-key host+tpm2` требует TPM 2.0 и привязывает credential одновременно к TPM и серверу. Без TPM ключ шифрования хранится на сервере: защищайте резервные копии, в которые могут попасть и credential, и ключ шифрования. Процесс бота получает ключ в открытом виде во время работы. Прежние копии `.env` всё ещё могут содержать старый ключ.

Для смены ключа передайте `--replace`: скрипт запросит новый ключ со скрытым вводом. Для проверки установленного credential используйте `--check-service`. Последующие запуски `update.sh` сохраняют credential и дополнение к systemd-юниту.

## Использование

- `/start` и `/help` показывают справку.
- Отправьте обычное текстовое сообщение. Код, конфигурации и журналы можно вставить текстом прямо в него.
- `/status` показывает текущий диалог, выбранную текстовую модель, доступность OCR и веб-поиска и сведения о последнем ответе. Внизу ответа бот указывает фактическую модель API, статус веб-проверки и номера переданных вложений.
- `/chat new Инцидент с сетью` создаёт отдельный диалог. `/chat` показывает номера, `/chat use ID` переключает, `/chat delete ID` удаляет неактивный диалог. Бот хранит до восьми диалогов в оперативной памяти.
- `/new` очищает историю и вложения текущего диалога.
- `/model` показывает доступные текстовые модели. `/model ИМЯ` выбирает модель для текущего диалога, `/model default` возвращает значение `LLM_MODEL`. Веб-запросы и изображения используют модели, предназначенные для этих возможностей.
- `/stop` отменяет текущую обработку и очищает очередь запросов этого пользователя. Запрос, который API уже принял, провайдер может обработать на своей стороне.
- Кнопка «Повторить другой моделью» появляется под последним ответом на текстовый запрос, если доступны альтернативы из `LLM_MODELS`. Она использует тот же вопрос, историю и текстовые вложения. Веб-запросы и изображения используют назначенные для них модели. Изменение списка вложений аннулирует старую кнопку.

### Доступ для других пользователей

1. Передайте пользователю ссылку на своего бота. Он открывает личный чат, отправляет `/id` и сообщает вам числовой ID.
2. В своём чате с ботом отправьте `/allow 123456789 Анна`. Имя после ID — произвольная подпись для списка.
3. Пользователь открывает `/start` и начинает работу. `/users` показывает выданные доступы, а `/revoke 123456789` отзывает доступ, отменяет текущую работу пользователя и удаляет его диалоги из памяти бота.

Гостям доступен запрос собственного ID. Только владелец из `ADMIN_ID` управляет разрешениями. Диалоги и вложения пользователей изолированы друг от друга, запросы используют ключ и лимиты настроенного провайдера. Список доступа переживает рестарт и хранится в `/var/lib/llmbot/access.sqlite3` при системной установке, у обычного пользователя — в `$XDG_STATE_HOME/llmbot` (по умолчанию `~/.local/state/llmbot`).

### Разбор инцидентов

Создайте диалог, отправьте журналы, конфигурацию и скриншоты, затем выполните `/incident` или `/incident После обновления узел перестал получать адрес по DHCP`. Бот выделит симптомы, подтверждённые факты, гипотезы, проверки и критерии передачи на ЛТП3. Он предлагает диагностические команды в ответе.

- `/find --from 14:20 --to 14:30 timeout` ищет по полному загруженному тексту. Бот показывает число совпадений и соседние строки. Можно искать только по фразе или только по временному интервалу. Для интервала с датой передайте ISO-метки, например `2026-11-22T14:20:00+03:00`, и используйте журнал с полными метками, например `journalctl -o short-iso`. Для времени суток без даты подходят обычные строки syslog. Часовые пояса в ISO-метках нормализуются к UTC; метки без зоны сравниваются в записанном виде.
- После `/find` следующий разбор использует найденные фрагменты. `/find reset` возвращает выбор фрагментов по вопросу и ключевым ошибкам. Для больших файлов бот отбирает релевантные строки по всему вложению в пределах контекста.
- В ответе бот сопоставляет ссылки модели с фактически переданными номерами строк или страниц и добавляет фрагменты текстовых источников. Для скана он указывает страницу, изображение которой было передано модели. Сопоставление проверяет ссылку, а инженер сверяет сам вывод с приведённым фрагментом.
- `/export` выгружает последний `/incident` текущего диалога в Markdown с запросом, разбором, доказательствами и списком вложений.

### Веб-поиск и чтение страниц

- При `LLM_WEB_TOOLS=auto` бот распознаёт в обычных сообщениях без вложений запросы с URL и ряд запросов на актуальные сведения, в том числе характеристики товаров и погоду. На прямом API DeepSeek эти запросы идут на `deepseek-flash` с веб-инструментами, независимо от настройки текстовой модели. Если текстовая модель уже `deepseek-flash`, веб-инструменты доступны и для остальных обычных сообщений без вложений.
- Команда `/web вопрос` отправляет запрос на `deepseek-flash` с веб-инструментами без вложений и без предыдущих ответов по ним. Модель, выбранная в диалоге, сохраняется.
- Бот добавляет ссылки, когда DeepSeek вернул источники. Для запросов на веб-проверку без источников бот повторяет запрос один раз и сообщает, если подтверждения по-прежнему нет. В журнале сервиса видно, когда потребовалась повторная проверка.
- Для OpenRouter, Ollama и других провайдеров бот использует обычный текстовый запрос. Веб-инструменты DeepSeek выполняются на стороне DeepSeek.

### Файлы и изображения

Прикрепите документы или фотографии и задайте один общий вопрос после загрузки. Вопрос в подписи к отдельному файлу запускает анализ сразу. Для группы файлов отправьте вопрос отдельным сообщением после подтверждений загрузки. Бот использует вложения активного диалога и при уточняющих вопросах.

`/files` показывает номера файлов, `/files remove ID` удаляет конкретный файл, `/files clear` освобождает все вложения активного диалога. Предыдущие ответы можно очистить командой `/new`.

| Вложение | Поддержка |
| --- | --- |
| PDF, DOCX, TXT, LOG, MD, CSV, INI, JSON, YAML и другие текстовые конфиги | До 10 МиБ на документ. Обычный текст доступен для поиска целиком. Для PDF и DOCX бот извлекает до 24 000 символов, для PDF — из первых 50 страниц. Поддерживаются UTF-8, UTF-16 с BOM и Windows-1251. |
| Сканированные и смешанные PDF | Для PDF из первых 50 страниц бот передаёт до шести страниц без текстового слоя модели распознавания. Для большего скана разбейте документ по страницам. |
| Фото Telegram и файлы JPEG, PNG, WebP, GIF | До 8 МиБ на изображение. Для мелкого текста на скриншоте отправьте изображение как файл, чтобы Telegram сохранил оригинал. |

На диалог доступно до восьми файлов и суммарно до 12 изображений, включая растровые страницы PDF, и до 16 МиБ закодированных изображений. Для вложений одного пользователя во всех диалогах действует лимит 64 МиБ памяти. Бот передаёт за запрос до 48 000 символов из всех документов. Если часть файла не вошла в запрос, бот указывает его номер под ответом.

Бот держит вложения, историю и выбор модели по каждому диалогу в оперативной памяти. При перезапуске процесса эти данные сбрасываются. Извлечённый текст и изображения передаются выбранному провайдеру только при анализе. Перед передачей текста бот маскирует типовые токены, пароли, заголовки авторизации и блоки приватных ключей. Маскирование основано на шаблонах и не применяется к содержимому изображений и страницам, отправляемым на OCR.

PDF и DOCX разбираются в отдельном процессе с ограничением памяти и времени. Если файл слишком сложный или разбор завис, бот останавливает процесс и сообщает об ошибке, не блокируя остальные запросы; `/stop` прерывает и текущий разбор.

## Обновление

Распакуйте новый архив **в отдельный каталог**. При системной установке запустите новый скрипт из распакованного каталога от root. Скрипт обновит код и зависимости в `/opt/llmbot`, установит недостающий промпт форматирования и перезапустит сервис.

```bash
bash update.sh
```

Для пользовательского сервиса выполните от его владельца:

```bash
bash update.sh --target /путь/к/установленному/llmbot
```

Для установки с ручным запуском добавьте `--no-service` и после обновления перезапустите процесс вручную. Скрипт сохраняет `.env`, `prompt.txt` и существующие настройки форматирования.

При обновлении с прежней модели на прямом API DeepSeek распознаваемые веб-запросы и команда `/web` используют `deepseek-flash`. В этом же режиме анализ изображений доступен с `LLM_VISION_MODEL=auto`, включая конфигурации, в которых этот параметр ещё отсутствует.

## Диагностика

Для системного сервиса выполните от root `systemctl status llmbot.service` и `journalctl -u llmbot.service -n 50 --no-pager`. Для пользовательского сервиса выполните следующие команды.

```bash
systemctl --user status llmbot.service
journalctl --user -u llmbot.service -n 50 --no-pager
```

| Симптом | Что проверить |
| --- | --- |
| Бот молчит на `/start` | Запущен ли сервис и открыли ли вы чат нужного бота |
| Пользователь получает сообщение о закрытом доступе | Сверьте ID из его команды `/id` со списком `/users` у владельца |
| Telegram сообщает о конфликте polling | Остановите второй процесс, который использует тот же токен |
| LLM API возвращает HTTP 401 или 403 | Проверьте ключ и права на использование модели |
| LLM API возвращает HTTP 404 | Проверьте базовый URL, имя модели и наличие модели у провайдера |
| LLM API возвращает HTTP 429 | Проверьте лимиты и баланс провайдера |
| Локальная модель долго отвечает | Убедитесь, что API доступен с сервера бота. При необходимости увеличьте `LLM_TIMEOUT` |
