# llmbot

Telegram-бот для работы с LLM в личных чатах: диалоги с историей, вложения (PDF, DOCX, текстовые файлы, изображения), веб-поиск и чтение страниц, разбор инцидентов и выгрузка отчётов.

Работает с любым OpenAI-совместимым Chat Completions API: прямой API DeepSeek, OpenRouter, локальная Ollama и другие. Запускается через Telegram long polling — входящий порт и белый IP не нужны.

## Возможности

- Текстовые вопросы к выбранной модели; длинные ответы делятся на сообщения, поддерживается разметка Telegram (код, цитаты, спойлеры).
- До восьми диалогов на пользователя, переключение и удаление через `/chat`, сброс через `/new`.
- Вложения: PDF (до 50 страниц), DOCX, текстовые файлы и конфиги, фото и изображения; OCR для сканов при настроенной vision-модели.
- Веб-поиск и чтение страниц на прямом API DeepSeek, команда `/web`.
- Разбор инцидентов: `/incident`, поиск по журналам `/find`, выгрузка в Markdown `/export`.
- Доступ по списку пользователей: `/allow`, `/revoke`, `/users`, собственный ID через `/id`.
- Защита: маскирование типовых секретов перед отправкой провайдеру, опциональное шифрование API-ключа через systemd credentials.

Полное руководство — в [HELP.md](HELP.md).

## Требования

- Python 3.10 или новее.
- Исходящий доступ к `api.telegram.org`, к API выбранной модели и к PyPI (или настроенному зеркалу).
- Linux с systemd для работы в режиме сервиса. Поддерживаются APT (Debian, Ubuntu) и DNF/YUM (РЕД ОС, Fedora, RHEL).

## Установка

```bash
unzip llmbot-1.4.3.zip
cd llmbot
bash install.sh
```

Скрипт сам определит режим: от root создаётся системный сервис в `/opt/llmbot` с настройками в `/etc/llmbot/.env`, от обычного пользователя — пользовательский сервис. Мастер запросит `BOT_TOKEN`, `ADMIN_ID` и параметры модели. Для запуска без systemd используйте `bash install.sh --no-service`.

Подробности, ручная установка, обновление и диагностика — в [HELP.md](HELP.md).

## Конфигурация

Настройки читаются из `.env` (шаблон — [.env.example](.env.example)):

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_ID` | Числовой Telegram ID владельца |
| `LLM_BASE_URL` | Базовый URL OpenAI-совместимого API |
| `LLM_MODEL` | Модель по умолчанию |
| `LLM_API_KEY` | Ключ провайдера |
| `LLM_TIMEOUT`, `HISTORY_TURNS`, `LLM_WEB_TOOLS`, `LLM_VISION_MODEL` | Необязательные параметры |

Файл `.env` не попадает в репозиторий. Для системной установки ключ можно вынести в зашифрованный systemd credential:

```bash
/opt/llmbot/.venv/bin/python /opt/llmbot/encrypt-api-key.py
```

## Структура

| Файл | Назначение |
| --- | --- |
| `bot.py` | Точка входа, обработчики команд и запросов к LLM |
| `access.py` | Список доступа и очередь запросов |
| `attachments.py` | Загрузка, извлечение текста и OCR вложений |
| `sandbox.py` | Изолированный разбор PDF и DOCX: отдельный процесс, лимит памяти и таймаут |
| `dialogues.py` | Диалоги и история |
| `evidence.py` | Поиск по журналам и сборка разбора инцидента |
| `redaction.py` | Маскирование секретов перед отправкой провайдеру |
| `telegram_format.py` | Разметка ответов для Telegram |
| `credentials.py`, `encrypt-api-key.py` | Чтение и шифрование API-ключа |
| `install.sh`, `update.sh`, `*.service` | Установка, обновление и systemd-юниты |

## Безопасность

- Не коммитьте `.env` и файлы с ключами: они уже перечислены в `.gitignore`.
- Перед отправкой текста провайдеру бот маскирует типовые токены, пароли и приватные ключи по шаблонам; маскирование не применяется к изображениям и OCR-страницам.
- PDF и DOCX разбираются в отдельном процессе с жёстким таймаутом и лимитом памяти; тяжёлый или повреждённый файл не блокирует бота, а `/stop` прерывает и сам разбор.
- Системный сервис работает в песочнице systemd (`ProtectSystem=strict`, `PrivateTmp`, `PrivateDevices` и др.). Пользовательский сервис ограничен capabilities и сетевыми семействами: опции с mount namespace не включаются, чтобы он запускался и там, где unprivileged user namespaces запрещены.
- Доступ к боту закрыт: посторонний пользователь получает только собственный ID.
